# PCBridge 1.7.0 — Computer Use для Windows

[Гибридный Computer Use и структурированный запуск процессов](PCBridge-1.7.0-Hybrid-Computer-Use.md)

Добавлен семантический доступ к интерфейсу через Windows UI Automation. Изменяется только `C:\Users\MaDeInCCCP\Documents\PCBridge — копия`.

## Что доступно

| Инструмент | Назначение |
|---|---|
| `ui_snapshot(window, max_nodes=200, max_depth=8)` | Структура одного окна: элементы, роли, имена, состояния, действия и ссылки |
| `ui_find(snapshot_id, text, role, limit=30)` | Поиск по уже полученному снимку без повторного чтения всего интерфейса |
| `ui_action(snapshot_id, ref, action, value, expect_text)` | Действие по ссылке на конкретный элемент, затем новый снимок и проверка результата |
| `ui_wait(window, text, role, present, timeout_seconds)` | Ожидание появления/исчезновения видимого элемента или текста |

Наблюдение включается существующим модулем `enable_screen`; действия также требуют `enable_input`. В режиме «только чтение» действия запрещены до запуска UI-процесса. Пауза запрещает все эти инструменты. Настройки и токены подключения не менялись.

Зависимости: `pywinauto>=0.6.8,<0.7`, `comtypes>=1.4.8,<2`. Они уже установлены в окружение этой копии. START/SETTINGS автоматически устанавливает их при включённом модуле экрана. Сервер импортирует только стандартную библиотеку управляющего модуля; COM загружается лениво в отдельном процессе.

## Как агенту работать

1. `list_windows()` — выбрать нужное окно.
2. `ui_snapshot(window="hwnd:12345")` — получить `snapshot_id` и элементы.
3. `ui_find(snapshot_id="...", text="Сохранить", role="Button")` — найти кнопку.
4. `ui_action(snapshot_id="...", ref="e12", action="invoke", expect_text="Сохранено")`.
5. Проверить `verification.verified`. Для следующего действия использовать **новые** `snapshot.snapshot_id` и refs из результата.

Параметр `window=""` означает текущее активное окно. Можно указать название или exe, но неоднозначность требует явного `hwnd:`: мост не выбирает произвольное совпадение.

`set_value` заменяет значение поля; `toggle` переключает флажок; `select` выбирает элемент; `expand`/`collapse` раскрывают или сворачивают; `scroll` принимает `value="up"`/`"down"`. В `elements[].actions` перечислены поддерживаемые действия. Автоматического перехода к клику по координатам нет: если элемент не поддерживает действие, мост сообщает об этом, а агент может отдельно использовать существующие screenshot/OCR-инструменты.

## Надёжность и пределы

- UI Automation выполняется в изолированном MTA-процессе. Зависший провайдер интерфейса не блокирует файловые инструменты сервера.
- Стандартный таймаут — 15 секунд; настройка `uia_timeout_sec` ограничена 3–30 секундами. У `ui_wait` есть дополнительный срок ожидания условия, не больше 30 секунд.
- По таймауту UI-процесс завершается. Следующее наблюдение запускает новый процесс. Если таймаут возник во время действия, его исход считается неизвестным: **сначала наблюдать, не повторять ввод автоматически**.
- Снимок действителен 120 секунд; новый снимок, действие или перезапуск делают старые ссылки недействительными. Проверяются идентичность окна, PID и время создания процесса, runtime ID, роль/имя элемента, принадлежность окну, видимость и доступность.
- `ok` и `action_executed` сообщают о выполнении операции. Они не доказывают достижение цели. `verification.verified` отдельно проверяет значение/состояние или ожидаемый текст. Если после выполненного действия окно недоступно, возвращается `observation_error`, а не команда повторить действие.
- Парольные значения и их поддеревья не возвращаются. В журнале аргумент `value` заменяется длиной строки. Снимки не пишутся автоматически на диск; журнал UI-процесса содержит диагностику, не весь интерфейс.
- По умолчанию захватывается до 200 узлов глубиной 8; максимумы — 500 и 15. `truncated` и `unreadable_nodes` показывают неполноту. Поиск работает только по захваченным узлам. Неполное дерево не считается доказательством исчезновения элемента.
- `include_bounds=true` добавляет координаты `[left,top,right,bottom]` в экранных пикселях; процесс включает DPI awareness. Сам UIA-ввод не использует координаты.
- Игры, canvas, некоторые Electron-приложения, защищённый рабочий стол/UAC и окна с повышенными правами могут предоставлять неполное дерево или отказывать в доступе. Существующий OCR остаётся резервом. Браузерный DOM/Playwright-модуль реализован; см. BROWSER.md. Дополнительные UI-инструменты описаны в AGENT_IMPROVEMENTS.md.

## Проверка

На Windows выполнен весь набор: **151 тест, OK (skipped=3)** — 148 пройдено, 3 fake-Unreal проверки применимы только к Linux/macOS.

В отдельном собственном WinForms-окне проверены чтение дерева, заполнение поля, вызов кнопки с изменением текста, переключение флажка, ожидание условия, маскировка пароля и отказ от повторного использования ссылки. Другие окна тест не менял. Проверены авария/таймаут отдельного worker, устаревшие ссылки, заменённое окно, неоднозначный выбор, ограничения обхода, отключённые модули, пауза и режим чтения. Остались прежние ResourceWarning старых HTTP-тестов; новых ошибок журналирования нет.

Предыдущие серверные файлы и setup.ps1: `backups/before-computer-use-20261115`.

## Загрузка обновления

Нужно перезапустить MCP-сервер целевой копии. Если клиент кэширует инструменты, обновить подключение/список MCP-инструментов: должны появиться `ui_snapshot`, `ui_find`, `ui_wait`, `ui_action`. При включённых screen/input поле `server_info.computer_use.enabled` равно true.
