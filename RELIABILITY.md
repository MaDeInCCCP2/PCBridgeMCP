## Пакетные правки

1. Вызвать `preview_file_edits(files=[...])`. Каждый элемент содержит `path`, массив `edits` и необязательный `expected_sha256`. Каждый edit: `old_string`, `new_string`, необязательный `replace_all`.
2. Просмотреть возвращённый diff и `plan_id`. Preview не меняет целевые файлы, но сохраняет план и резервные байты на диске.
3. Вызвать `apply_file_edits(plan_id=...)`. Мост проверяет хеши всех файлов, затем ещё раз перед заменой каждого файла. Повторный вызов завершённого плана не повторяет запись.
4. `undo_change(change_id=...)` отменяет пакет одной записью истории. Если после пакета файл был изменён, отмена отказывается перезаписывать его.

Пример аргументов preview:

```json
{
  "files": [
    {"path": "src/a.rs", "edits": [{"old_string": "old_a", "new_string": "new_a"}]},
    {"path": "src/b.rs", "edits": [{"old_string": "old_b", "new_string": "new_b"}]}
  ]
}
```

Пакеты поддерживают 1–100 существующих UTF-8 файлов; CRLF и BOM сохраняются. Общий объём исходных и новых байтов ограничен `backup_max_mb`. Новый файл можно создать через `write_text_file(expected_sha256="absent")`. Дубликаты путей и повреждённые планы отклоняются.

При ошибке во время применения мост пытается восстановить уже изменённые файлы. Если содержимое отличается и от исходной, и от записанной мостом версии, оно сохраняется, а ответ получает `recovery_required` и перечень проблем.

`file_edit_status()` показывает последние планы; `file_edit_status(plan_id=...)` — подробный журнал. После аварийного завершения процесса незавершённый пакет остаётся в состоянии `applying`; вызвать `recover_file_edits(plan_id=...)` для явного отката. Восстановление также сохраняет чужие правки. Журналы и исходные/новые версии лежат в `history/transactions`.

Это последовательные атомарные замены отдельных файлов с журналом и откатом, а не единая транзакция файловой системы: другие приложения могут видеть промежуточное состояние. Блокировка упорядочивает файловые операции внутри одного процесса PCBridge. Проверки хешей обнаруживают устаревшие версии; они не заменяют общую блокировку с внешними редакторами. Журналы планов пока не удаляются автоматически — их нельзя удалять, пока нужен план или аварийное восстановление.

## Проверка версии одного файла

`file_info(path=...)` возвращает `sha256`; `read_text_file` также показывает хеш прочитанных исходных байтов в заголовке.

`write_text_file`, `edit_file`, `edit_file_multi` принимают необязательный `expected_sha256`. Несовпадение даёт `file_conflict` и не применяет правку. Старые вызовы без этого аргумента сохранены. После записи возвращается новый `sha256`.

Если Windows не разрешает атомарную замену, возвращается ошибка: запасной перезаписи с предварительным обнулением файла больше нет.

## Долгие задачи

`run_command(background=true)` и существующие инструменты сборки/рендера используют отдельный `job_worker.py`. Он записывает настоящий код завершения дочерней команды независимо от жизни MCP-сервера. Метаданные находятся в `logs/jobs`, вывод — в `logs/job_<id>.log`.

`job_status` сохраняет прежние поля и добавляет `status` и `recovered`:
- `running`: задача выполняется;
- `completed`: получен код 0;
- `failed`: команда завершилась с ошибкой или не запустилась;
- `stopped`: мост остановил задачу;
- `unknown`: достоверный исход недоступен. Это не успех.

После перезапуска мост загружает задачи с диска. Идентичность процесса проверяется по PID и времени создания; задача с переиспользованным PID не считается прежней и не останавливается. Завершение всех процессов дерева супервизором/Windows может прервать и наблюдателя: тогда честный результат — unknown, если код не успел сохраниться. Восстановление процесса после перезапуска всего Windows не обещается.

## Вывод по курсору

Вызвать `read_job_output(job_id=..., cursor="", max_bytes=16000)`. На следующем шаге передать `next_cursor` как `cursor` без изменений. Ответ содержит `text`, `next_cursor`, `has_more`, `offset`, `reset` и `status`.

Курсор привязан к задаче, файловому идентификатору и контрольному фрагменту предыдущих байтов. Замена/обрезка лога даёт `reset=true` и чтение с начала. Незавершённый UTF-8 символ остаётся для следующего чтения; ограничение ответа — до 1 МБ. Вывод предполагается UTF-8; для иных кодировок возможны символы замены. Не опрашивать в бесконечном цикле без пауз.

## MCP-совместимость

Для инструментов с результатом-словарём возвращаются текстовый JSON и `structuredContent`. Прежние поля остаются на верхнем уровне; добавлено `ok`. Ошибки включают `error`, `error_code`, `details` и MCP `isError=true`. Текстовые инструменты сохраняют текстовый формат. Вызовы Python напрямую сохраняют прежний тип и исключения.

Справочные источники, использованные при разработке:
